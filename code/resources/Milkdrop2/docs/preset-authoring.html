Preset Authoring

Write your own visuals: animate motion with equations, draw custom shapes and waveforms, and finish the image with pixel shaders. All of it is edited live, while the music plays.

.milk filesEEL expressionsHLSL pixel shaders (SM 2 / 3)

How a preset works #

Every frame, MilkDrop takes the previous frame's image, warps it slightly, draws new things on top, and shows the result. Because each frame feeds the next, small motions add up to the flowing look MilkDrop is known for.

A preset is a plain-text .milk file holding:

  • Static values: zoom, rotation, wave color and so on, set from the M menu.
  • Init code: runs once when the preset loads.
  • Per-frame code: runs once per frame and animates the values over time and with the music.
  • Per-vertex code: runs at every point of a mesh across the screen, so motion can differ by position.
  • Up to 4 custom shapes and 4 custom waves, each with its own code.
  • Two pixel shaders (HLSL): warp and composite.

Editing on screen #

  1. Lock the preset first with ` or Scroll Lock, so MilkDrop doesn't move on while you work.
  2. Press M. The menu has sub-menus for motion, custom shapes, custom waves, waveform, augmentations and post-processing, plus items to edit the init code, per-frame and per-vertex equations, and the warp and composite shaders.
  3. In a code editor, press Ctrl+Enter to apply. Errors show in the corner of the screen. While editing a shader, F9 shows a quick reference.
  4. Save with S (new name) when you're happy.
Old presetsMilkDrop 1 presets have no pixel shaders. Choose upgrade preset's pixel shader version in the menu to get default warp and composite shaders that reproduce the old look, then edit them. Keys like g/G (gamma) and q/Q (echo) only work on old presets; in upgraded ones, change the composite shader instead.

Quick tweak keys (all listed in the User Guide): i/I zoom, [ ] { } push, < > rotate, o/O warp, w/W wave type, j/J wave size, e/E wave opacity.

Expression language #

Init, per-frame, per-vertex, shape and wave code use the same small language (EEL). Statements end with ;. Every value is a number. A variable you assign is created automatically.

// per-frame: zoom breathes with time, spins harder on bass
zoom = 1 + 0.05*sin(time*1.3);
rot  = rot + 0.02*(bass_att - 1);
wave_r = 0.5 + 0.5*sin(time*1.13);
wave_g = 0.5 + 0.5*sin(time*1.23);
wave_b = 0.5 + 0.5*sin(time*1.33);

Staggering the speeds (1.13, 1.23, 1.33) keeps the three color channels from moving together, which would only give gray.

Per-vertex variables #

Per-vertex code runs at each point of the mesh (nMeshSize, 64 by default) and the result is blended smoothly between points. It can set the same motion values as per-frame code (zoom, zoomexp, rot, warp, cx, cy, dx, dy, sx, sy), but differently at every point. It can also read time, audio, mesh and screen values, and q1-q32. On top of that it gets the position of the current point:

NameRangeMeaning
x, yread0..1Position of the point; 0, 0 = top-left
radread0..1Distance from the center; 0 at the center, 1 at the corners
angread0..2πAngle around the center; 0 = right, π/2 = up
 
// per-vertex: zoom more toward the edges, for a sense of depth
zoom = zoom + rad*0.1;
Rule of thumbIf a per-vertex line doesn't use x, y, rad or ang, it gives the same result everywhere, so move it to the per-frame code. That's much faster.

Variable pools, q and t #

Your own variables live in a pool and can't be seen from other pools. Values persist from frame to frame within a pool. The pools are:

  1. Preset init + preset per-frame code
  2. Each custom wave's init + per-frame code
  3. Each custom shape's init + per-frame code

Per-vertex code and wave per-point code have no persistent variables; treat anything you create there as scratch. To pass values between pools, use the shared q1-q32, and for waves and shapes also t1-t8.

  • Values written to q in the init code become the starting values for every frame.
  • Per-frame code can change them; per-vertex code, shapes, waves and shaders see the changed values for that frame.
  • q values written in shape or wave init code go nowhere. Use your own variables there instead.
  • t1-t8 work the same way, but only inside one wave or shape: from its init code to its per-frame code, and for waves on to the per-point code.
  • Editing the init code and pressing Ctrl+Enter runs it again right away. Editing other code does not re-run init; reload the preset for that.

Custom shapes #

Each preset can have 4 shapes: polygons with 3 to 100 sides, drawn anywhere, any size and color. A shape can be filled with the previous frame's image (textured), which makes feedback fractals possible. With instancing a single shape is drawn up to 1024 times per frame, each copy with its own values.

Pixel shaders #

Pixel shaders are small HLSL programs that run for every pixel, every frame, on the graphics card. Each preset has two. Your code goes between shader_body { and }, and whatever ends up in ret (a float3 color, 0..1) is the result. Declarations such as samplers go above shader_body.

MilkDrop supports shader model 2 (64-instruction limit) and shader model 3 (practically unlimited). A preset that needs more than the graphics card supports is hidden from the list.

Warp shader

Runs over the internal canvas and writes back to it, so whatever you do here is "baked in" and carries into the next frame. uv holds the warped coordinates from your per-vertex code; uv_orig holds the original ones.

shader_body
{
    // read the previous frame at the warped position: this creates the motion
    ret = tex2D(sampler_main, uv).xyz;
    // fade a little each frame so the screen doesn't fill up with white
    ret = (ret - 0.002) * 0.99;
}
Fading over timeThe canvas holds 8 bits per channel. With ret *= 0.97 alone, keep the factor at 0.98 or lower, or dark pixels never reach black. ret -= 0.004 always reaches black but can feel abrupt. Combining the two, as above, usually looks best.

Composite shader

Runs once per frame to produce what you see. Nothing here affects the next frame, so it's the place for color grading, mirroring and other display effects.

shader_body
{
    ret = tex2D(sampler_main, uv).xyz;
    ret = max(ret, tex2D(sampler_main, 1 - uv).xyz); // mirror on both axes, keep the brighter pixel
    ret = pow(ret, float3(0.5, 1, 2));             // warm tint: curve each channel differently
    ret *= 1.6;                                     // slightly over-bright for punch
}

Blur

GetBlur1, GetBlur2 and GetBlur3 return progressively blurrier copies of the canvas. Each is only computed when a shader actually uses it, and each level is built from the one before it, so Blur3 costs the most. Edge detection:

ret = abs(tex2D(sampler_main, uv).xyz - GetBlur1(uv)) * 4;

Glow from bright areas only: set blur1_min = 0.7 in per-frame code, then add ret += (GetBlur1(uv) - blur1_min) * 2;

NameKindSizeQuality
noise_lq2D256×256Low

Use the smallest that works. To map noise 1:1 to screen pixels and move it every frame (a good dither):

float4 texsize_noise_lq;          // above shader_body: MilkDrop fills in the size
shader_body
{
    float2 nuv = uv_orig * texsize.xy * texsize_noise_lq.zw + rand_frame.xy;
    ret = tex2D(sampler_main, uv).xyz;
    ret += (tex2D(sampler_noise_lq, nuv).xyz * 2 - 1) * 0.01;
}

Only use the medium and high quality noise when zoomed in on it. Sampling it at 1:1 or smaller wastes the cache and slows the preset down a lot.

Your own images

Put the image in plugins\Milkdrop2\textures\ or next to the preset, and declare a sampler named after the file, without its extension:

sampler sampler_clouds;           // loads clouds.jpg (or .dds, .png, .tga, .bmp)
float4  texsize_clouds;           // optional: its size
shader_body
{
    ret = tex2D(sampler_clouds, uv * aspect.xy).xyz;           // fit to screen
    // tex2D(sampler_clouds, uv * texsize.xy * texsize_clouds.zw)  -> 1:1 pixels
    // tex2D(sampler_clouds, (uv-0.5)*0.2 + 0.5)                   -> zoom into the center
}

Random textures: name the sampler sampler_rand00 to sampler_rand15 and MilkDrop picks a random image from the textures folder. Add a prefix to choose only among matching files: sampler_rand02_smalltiled picks only files whose names start with "smalltiled".

Keep shared textures small (256×256 or less, JPG at about 95%), so presets download fast and load without a pause.

Shader tricks

  • Darken only the center of a zoom (warp shader): ret *= 0.97 + 0.03*saturate(length(uv - uv_orig)*200);
  • Soft max for values in 0..1: a + b - a*b blends more smoothly than max(a, b).
  • Aspect-correct offsets: when you nudge uv in the warp shader, multiply the offset by aspect.xy, so it looks the same in wide and tall windows.

Quality & performance #

  • Compute once, not per pixel. A value that's the same everywhere belongs in per-frame code; hand it to shaders and per-vertex code through q.
  • Slow motion goes in per-vertex code, fine detail in the shader. Per-vertex runs on the CPU at a few thousand points; shaders run on millions of pixels.
  • Avoid in shaders: if, sin/cos with per-pixel inputs, and sampling textures heavily zoomed out.
  • Multiply instead of dividing in equations: compute inv = 1/v; once and multiply.
  • Check square and wide windows. Use aspectx/aspecty in equations and aspect in shaders.
  • Test with the default mesh size (64), so others see what you designed.
  • Don't build effects on progress. How fast it moves depends on each user's auto-change time.
  • Remember dx and dy. With everything else off, they give exact control over the motion; every other motion effect can be expressed with them.
  • The shader compiler removes unused work, such as ret *= 1 or a texture that never reaches ret, so experimenting is cheap.

Debugging #

Press N to show the monitor, then add a line to the per-frame code and apply with Ctrl+Enter:

monitor = q3;      // the value appears in the top-right corner

The monitor works in per-frame code only. To watch a per-vertex quantity, compute it in per-frame code for one sample point. Code errors show in the corner of the screen when you apply; F9 opens the shader quick reference while you edit.
